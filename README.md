# Handraw Style Router V2

版本 **2.0.0**。用于 Codex：输入主题，从 handraw-style 风格库推荐五个不同方向；选中后用自然语言继续探索，或开启精细模式实际看参考图比较，最后交付可复制提示词与对应参考图。明确要求生图时，衔接 Codex 当前可用的生图工具。

## 安装：复制一条命令

**不用安装上游 handraw-style Skill，也不用手工下载或切分风格库图片。** 本Router会在首次使用时自动下载上游风格索引和每种风格对应的参考图片，并保存在本机。后续可以直接在具备生图工具的Codex环境中完成选画风和生图，无须另外填写API Key。

### 方式一：在终端执行（已有Node.js / npx）

1. 打开电脑上的“终端”（macOS）或PowerShell（Windows）。这条命令粘贴在终端里，不是浏览器地址栏。
2. 复制下面整行，粘贴后按回车：

```sh
npx --yes --package=skills -- skills add lacemou/handraw-style-router --skill handraw-style-router --agent codex --global --copy --yes
```

这条命令调用[开源Skills安装工具](https://github.com/vercel-labs/skills)，从本仓库安装 `handraw-style-router`，只针对Codex安装到用户级Skill目录，可跨项目使用。`--copy`表示复制文件，`--yes`跳过选择菜单；前面的 `npx --yes`免去安装工具本身的确认。它只安装Router源码和说明，**此时还没有下载完整风格参考图，也没有安装Python依赖**。

看到 `Installation complete` / `Installed 1 skill` 表示Skill文件安装完成。当前安装工具的Codex用户级目录是 `~/.agents/skills/handraw-style-router`；以命令实际输出的安装路径为准。如果已有同名Skill，先备份旧安装中的 `.runtime` 和自定义文件，再执行命令，避免覆盖本地修改。

若提示找不到 `npx`，说明当前终端没有可用的Node.js环境；可采用下面的方式二，让Codex完成安装准备。

### 方式二：不熟悉终端，就把这句话发给Codex

打开Codex聊天，复制并发送：

```text
请帮我把 https://github.com/lacemou/handraw-style-router 安装为用户级 Codex Skill。Skill 在仓库根目录，默认分支是 master，名称是 handraw-style-router。请使用可用的 Skill 安装器，检查 Python 3.10+ 和 Pillow 10+，准备所需依赖，执行一次 router.py init，自动下载并核验风格库参考图，最后告诉我实际安装路径和初始化结果。如果已有同名安装，请先保留旧版和本地运行记录再处理。
```

这是一条发给Codex的安装请求，不是终端命令。Codex会根据电脑上的实际环境准备安装；涉及联网、安装依赖或写入用户目录时，按界面提示允许对应操作即可。缺少Python或网络访问条件时，Codex会说明具体缺项，不能将“已下载Skill文件”当成“已可运行”。

### 安装后第一次使用

如果用了方式一，在Codex里发送：

```text
请使用 $handraw-style-router。首次使用请先检查 Python 3.10+ 和 Pillow 10+，准备依赖并初始化风格库。我的主题是“为什么AI不会累？”，先给我五个画风参考，不生图。
```

如果已经通过方式二完成初始化，直接发主题即可。安装后可在下一条消息调用Skill；若当前聊天没有识别它，另开一个Codex聊天，或把安装命令输出中的 `SKILL.md` 绝对路径交给Codex读取。

推荐出现后，可以说“选第3个，生图”，或“开启精细模式，我希望更有趣、更有反差”。Router使用当前Codex的生图工具；是否可直接生成取决于当前环境是否提供该工具。工具不可用时仍可交付提示词和参考图。

### 哪些地方需要等待？

| 阶段 | 实际发生什么 | 如何判断完成 |
| --- | --- | --- |
| 一条命令安装 | 下载安装工具与Router源码；不下载全库图片 | 终端显示安装完成和安装路径 |
| 首次初始化 | 检查依赖，自动下载风格索引与全库参考图，核验后启用 | Codex报告库已就绪及风格数量，随后展示候选 |
| 后续推荐 | 读取已缓存的风格库，分析主题并展示候选 | 画风编号、参考图和理由完整出现 |
| 精细模式 | 按你的反馈召回短名单，再实际看参考图比较 | Codex给出细选结果 |
| 生图 | 提交完整主题、用户补充与必要参考图给生图工具 | 工具返回图片；默认状态“已生成，未检查” |

**没有所有电脑都适用的固定等待时间。** 首次安装受npm与GitHub连接影响；首次同步还受参考图数量和网络速度影响；如果需要准备Python环境，时间会更长。第一次使用建议预留5–10分钟作为时间预算，网络不佳时可能超过这个预算，不是完成时限。后续已有本地缓存，不会每次重新下载全库图片；推荐、看图与生图的等待也受当前模型和服务状态影响。

2026年10月8日，在一次全新缓存的实测中，327种风格及对应参考图的下载、核验与启用共用 **约92秒**；Python和Pillow在测试前已可用。这个数字不包含Skill安装、模型对话和生图，也不代表其他网络下的耗时。安装命令的源码安装步骤已在隔离的项目目录验证成功；用户级安装参数按安装工具官方说明使用，未改动测试者的全局Skill。

### 需要去上游下载什么吗？

不用手动操作。首次初始化会从上游公开仓库自动获取：风格索引、对应参考图片、编号映射、模型能力策略和许可说明。目前已同步验证的风格库有327种，实际数量以初始化结果为准。用户无需下载上游Skill、整张图集或自己分割图片。资源保存在安装目录的 `.runtime/libraries/`；首次初始化需要联网，完成后日常选风格使用本地缓存。只有主动要求更新，才检查并同步上游新版本；未变化图片可复用。

手动安装仍可下载 [v2.0.0发布包](https://github.com/lacemou/handraw-style-router/releases/tag/v2.0.0)，解压到可用的Codex Skill目录，并将 `SKILL.md` 路径交给Codex。旧版源码保留在Git历史中。

## 工作方式

默认五候选保留不同推荐侧重点：最稳妥、最有表现力、最具故事感、最容易读懂主题、差异化候选。它们是选择提示，不是全库最优的保证。每轮快速候选后明确提示可选1–2个继续，或开启精细模式；数量可指定1–10；智能数量只在用户开启后使用。选中一或两个方向，分别探索邻近画风。锚点保留对照，新增候选标明路线，已看过而未选中的候选不反复推出。单路线最多5个，两条路线默认合计6个，最多10个。

快速模式：Codex解析主题/反馈，脚本按文字画像、视觉特征词与多样性进行初筛。精细模式：先取得用户具体反馈，再按反馈召回短名单并实际看图精排。仅说“开启精细模式”时，Skill先引导补充表达重点、情绪或视觉偏好；任选一个方面即可，已有有效细节不重复询问。短名单最多10个，默认展示5个，仍不是全库逐图比较。文字标签是启发式，不代表已完成全库视觉校准；尚无充分对照证据证明推荐质量普遍优于旧版。

历史只记选择、材料交付、当前Codex内可确认生成。外部生成未知；统计不参与推荐。任务进度只在当前会话继续，新任务从零开始。运行时会话文件不构成跨会话恢复功能。

## 命令与依赖

Python >=3.10，Pillow>=10.0。先安装 `requirements.txt`，使用绝对脚本路径；以下示例从本包根目录运行。

```sh
python3 -m pip install -r requirements.txt
python3 scripts/router.py init
python3 scripts/router.py check
python3 scripts/router.py start --conversation demo-current-chat --topic '为什么AI不会累？' --features-file topic.json
python3 scripts/router.py select --conversation demo-current-chat --styles FA-001 --event-id user-choice-1
python3 scripts/router.py explore --conversation demo-current-chat --feedback-file feedback.json
python3 scripts/router.py deliver --conversation demo-current-chat --event-id user-delivery-1 --model unknown
python3 scripts/router.py stats
python3 scripts/router.py update --check-only
python3 scripts/router.py update
```

上面的 `FA-001` 必须是当前结果中实际展示的风格，不能照抄示例选未展示的编号。CLI没有模型解析输入时明确标记关键词降级；正式使用由Codex形成JSON。feedback.json见 `references/feedback-contract.md`。`--smart`开启智能数量、`--fixed`关闭；`--count`给明确数量。

由当前Codex选择Python 3.10或更新的可用运行环境，不能直接使用不符合要求的系统Python。

## 更新与许可

用户主动更新才访问GitHub。更新把风格索引、编号别名、模型策略和完整参考图固定到同一上游提交。下载、图片读取、编号对应与评分冒烟检查通过后原子启用；失败保留原库。新增风格立即可推荐。新结构无法解析时明确失败，不忽略错误假装成功。未变化的Git图片blob复用本地文件。

当前任务固定开始时的库快照，更新不会暗中更换已经选择的风格。更新后新任务使用新库；旧快照保留供当前任务和回退。

统一更新入口分别报告资源库与代码。代码更新依赖本项目公开的版本化 `release.json` 和GitHub Release归档；通过本仓库默认分支的清单与对应Release归档获取更新；没有清单时明确报告代码更新尚不可用。

`python3 scripts/build_release.py` 生成源代码归档及发布清单，**不发布**。归档不含 `.runtime`、用户记录、测试运行结果或上游图片。代码升级校验归档与每个文件的SHA256、路径和Python语法，保留源码备份，写入异常回退。

本项目代码采用MIT。上游：yang0 / https://github.com/yang0/handraw-style 。上游目前采用MIT with Attribution Requirement：保留版权和许可，并展示作者和原仓库。同步快照与交付目录保留原许可文件。不能把软件许可扩大为所有第三方参考作品的权利授权。

## 隐私与网络范围

本Skill不要求API Key，不读取环境变量中的凭证，不上传主题、反馈或行为记录。主题、用户补充、候选状态与交付材料保存于本Skill的 `.runtime`，其中可能包含个人输入，请勿提交到公开仓库。首次资源同步与用户主动更新会访问GitHub；任务主题不会拼进网络请求。用户明确要求生图时，提示词与必要参考图会提交给当前环境的生图工具。源码仓库与发布包不含本地运行记录、开发记录、生成图片或上游参考图片。
